# Learning Patterns（教学模式参考）

本文件是 `personal-tutor` 的按需参考，不是每轮都要展示给学习者的课程讲义。需要选择模式、解释为什么这样练，或设计具体问题时阅读相关部分；执行时以 `SKILL.md` 的当前目标和学习状态为准。

## 设计原则

个人导师采用几条互补原则：

- **目标导向**：先定义可观察的最终表现，再反推必要知识，避免把主题覆盖率当成学习成果。
- **认知负荷控制**：先给最小心智模型，把复杂内容拆成小块；只在学习者遇到具体断点时补充解释。
- **主动提取**：优先让学习者回忆、预测、解释和产出，而不是连续阅读答案。正确答案只有在需要时揭示。
- **刻意练习**：练习要针对一个可识别的能力，带有明确反馈，并在接近掌握后提高难度或改变条件。
- **从错误学习**：错误是定位错误模型的证据。先追问断点，再给最小修正，最后用变体确认修正可迁移。
- **迁移验证**：真正掌握不只是复现原题，还包括处理边界、异常、信息缺失和未见过的场景。
- **间隔复习**：在本次学习结束后安排短复习和延迟迁移，防止一次会做被误判为长期掌握。

这些原则是决策依据，不是需要机械执行的理论清单。时间、风险和学习者表现可以改变具体顺序。

## 六个模式的来源与用法

下面六个模式改写自引用对话中的提示词。它们是可调的教学动作，不应被当成每次固定运行的六个独立提示。

### 1. 学习曲线破坏者（Scope Cutter）

**解决的问题**：学习者把“学会一个主题”误当成覆盖全部知识，时间却有限。

**核心动作**：把内容分为“现在必须学 / 暂时忽略 / 之后再学”，然后设计一个能调用大部分核心能力的 `Keystone Exercise`。

**什么时候用**：启动、目标变更、时间缩短，或学习范围开始失控时。

**设计提示**：被列为“现在必须学”的内容必须能指向最终实战中的具体步骤或判断；暂时忽略不等于永远不重要。

### 2. 真实错误模拟器（Error Simulator）

**解决的问题**：学习者能认出解释，却不会在真实场景中作出正确决策。

**核心动作**：给场景和任务，让学习者先行动。第一次错误只暴露位置并追问；第二次仍错才给最小答案和缺陷诊断，再用相近变体重做。

**什么时候用**：学习者“理解但不会做”、需要操作技能，或已经有最小概念骨架时。

**边界**：安全风险、高风险专业决策或极端时间限制下，不为了模拟错误而隐去必要警告或答案；可以先保护结果，再解释断点。

### 3. 困惑破碎机（Confusion Breaker）

**解决的问题**：学习者面对一段材料或概念时，不知道最关键的理解支点是什么。

**核心动作**：先给一句话锚点，再用日常类比，随后映射到正式概念、公式或 API；最后提出一个辨别题、一个因果题和一个轻度迁移题。

**什么时候用**：首次介绍关键概念，或学习者明确说“困惑 / 没懂 / 为什么”时。

**边界**：类比只用于建立入口，必须说明它与正式机制的对应关系和差异；不要一开始堆出完整章节。

### 4. 个人学习路径（Personal Path）

**解决的问题**：计划看似完整，却没有连接到学习者的真实目标、截止期和已有基础。

**核心动作**：以 `Target`、`Deadline`、`Baseline` 和 `Constraints` 生成时间块或天数路线；每段只有一个主要结果，并配动作、通过标准和避免事项。

**什么时候用**：每次启动、截止期改变、已有路径无法达到目标时。

**默认模板**：4 小时按 `SKILL.md` 的时间表；约 7 天时每天安排一个约 45 分钟的核心任务。两者都是起点，必须按主题和证据调整。

### 5. 隐藏漏洞检测器（Blind-Spot Audit）

**解决的问题**：学习者可以复述熟悉题目，却把表面熟练误认为真正理解。

**核心动作**：准备 5 个短问题，依次覆盖定义边界、原因、反例、条件变化和新场景；每题回答后指出它证明了什么或暴露了什么缺陷。

**什么时候用**：学习者已有初步熟练度、自称掌握，或进入最终实战前。

**顺序约束**：不要在零基础时用它作为第一步。发现关键漏洞时回到对应阶段补训，不把审计分数包装成掌握证明。

### 6. 强制费曼方法（Feynman Check）

**解决的问题**：学习者会背术语或步骤，却无法解释因果链、前提和失败条件。

**核心动作**：要求学习者用自己的话向 10 岁孩子解释“为什么成立、怎么工作、什么时候会失败”，一旦出现无法解释的术语、跳步、循环论证、冲突类比或错误简化，就停在第一个断点并要求重述。

**什么时候用**：完成一个主要知识块后，或发现“会做但说不清为什么”时。

**边界**：不要一次抛出一长串问题；先修复第一个断点，再继续检查。

## 推荐顺序与动态分支

默认主线是 `个人学习路径 → 学习曲线破坏者 → 真实错误模拟器 → 隐藏漏洞检测器`，即 `4 → 1 → 2 → 5`。这是优先级建议，不是固定脚本。

`困惑破碎机` 和 `强制费曼方法` 是按状态插入的纠偏模块：

| 学习者状态 | 首选模式 | 下一步 |
|---|---|---|
| 目标模糊或期限变化 | 个人学习路径 | 重建学习契约和路线 |
| 内容过多、时间不足 | 学习曲线破坏者 | 缩小到 `Keystone Exercise` |
| 首次接触、明确困惑 | 困惑破碎机 | 3 个理解题，确认锚点成立 |
| 理解概念但无法操作 | 真实错误模拟器 | 逐级提示、变体重做 |
| 会做但解释不清 | 强制费曼方法 | 修复第一个推理断点 |
| 自称掌握或准备收尾 | 隐藏漏洞检测器 | 暴露漏洞后回退补训 |
| 稳定正确 | 迁移变体 | 改变约束、信息或场景 |
| 连续失败 | 降低难度 | 回退一个前置概念 |

## 模式设计检查

设计或调用一个模式前，确认：

1. 它服务于当前 `Final Performance`，而不是为了让流程看起来完整。
2. 学习者有机会先作答或产出。
3. 通过标准能观察到，且不把关键词复述当成理解。
4. 错误反馈指出思维断点，并安排重新尝试或变体。
5. 模式结束后更新学习状态，决定继续、回退还是迁移。
